# 课堂演示与验收

## 1. 启动（约30秒）

双击 `start.cmd`。展示城市、日期、偏好、运行方式及数据来源。说明项目单一用途是“按天气挑选合适景点”。

## 2. 真实天气（约1分钟）

选择北京、今天、实时工具模式。点击查询，展示日期、数据类型、温度、降水、风速与来源。该模式没有调用LLM，用来独立证明天气与数据库工具能真实执行。

展开工具记录，展示 `get_weather` 与 `search_attractions` 的参数及结果；下载记录，说明它们是基础模型之外的上下文。

## 3. 小雨场景（约1分钟）

点击“北京零星小雨示例”。先指出黄色提示“模拟天气”，再展示室内景点和不推荐故宫/颐和园的原因。示例不能作为某个真实日期的天气证据。

## 4. 真正的 DeepSeek 代理（需自己的 API Key）

切换 DeepSeek AI 模式并配置密钥。输入补充需求，查询真实天气并生成解释。

检查工具记录：应包含模型发起的两项成功调用。下载 JSON，确认 `mode` 为 `deepseek`、模型名称正确、天气 `data_kind` 不是 `synthetic_fixture`。把真实运行输出留作最终作业证据。

## 5. 展示不是硬编码答案

更换城市、日期或偏好再次运行；展示数据和推荐随上下文变化。超出16天预报范围时应显示无法提供预报，而不是编造。

模型密钥未配置时，只能展示工具和模拟协议测试，不能宣称已完成真实 DeepSeek 端到端验收。

## 6. 解释三个作业要求

1. 工具技能：天气 API 查询 + SQLite 景点检索（未知城市尝试在线地图）。
2. 标准协议：DeepSeek Chat Completions 的 tools、tool_calls、role=tool、tool_call_id。
3. Vibe Coding：由 Codex 生成请求代码、工具参数模型、后端、界面、测试和启动器；重点设计系统提示词与编排。
